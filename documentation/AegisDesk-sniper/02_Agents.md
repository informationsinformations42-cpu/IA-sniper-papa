# 2. Catalogue des 17 agents

OVERLORD est l'assistant central. Les 16 autres agents sont des spécialistes. Les noms et rôles ci-dessous constituent le catalogue officiel du projet.

| Agent | Rôle prévu |
|---|---|
| **OVERLORD** | Assistant central, dialogue, coordination et synthèse. |
| **SENTINEL** | Protection et surveillance défensive du système local. |
| **PHANTOM** | Surveillance défensive du réseau et signalement d'événements suspects. |
| **WEBHAWK** | Audit défensif de sites web dans un périmètre autorisé. |
| **BLACKBOX** | Analyse défensive d'applications et de logiciels autorisés. |
| **HUNTER** | Détection et qualification de menaces. |
| **AEGIS** | Conseils et recommandations de défense. |
| **ARCHIVE** | Historique, rapports et classement des résultats. |
| **FORGE** | Assistance à la programmation et à la maintenance du code. |
| **PIXEL** | Création et analyse visuelles. |
| **ECHO** | Voix et communication audio. |
| **SPECTRE** | Analyse et corrélation défensives. |
| **ACADEMY** | Apprentissage, explications et accompagnement pédagogique. |
| **BREACH** | Analyse de vulnérabilités dans un périmètre explicitement autorisé. |
| **ORACLE** | Recherche, collecte et analyse d'informations. |
| **ARCHITECT** | Conception technique, architecture et organisation des modules. |
| **SNIPER** | Analyse de sécurité défensive et priorisation des constats. |

## Règles communes aux agents

- Un rôle décrit dans un prompt n'est pas la preuve qu'un module existe.
- Un agent ne peut être déclaré actif que si son module est présent, initialisé et prêt.
- Les agents doivent respecter le périmètre d'autorisation fourni.
- Les résultats doivent distinguer faits observés, hypothèses et recommandations.
- Les actions qui modifient un système nécessitent des permissions et confirmations adaptées.
- Les agents ne doivent pas se donner mutuellement des permissions supplémentaires.
